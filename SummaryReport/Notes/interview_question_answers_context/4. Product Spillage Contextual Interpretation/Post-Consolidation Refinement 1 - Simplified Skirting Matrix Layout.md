## Attached Example — Governing Intent

The attached example reframes the matrix around the specific management question:

> **Where is side skirting required, potentially applicable, or not presently indicated?**

The example uses a small number of binary fields:

- inspected section / conveyor;
- area;
- coarse-product present;
- coarse-product localized;
- coarse-product widespread;
- skirting candidate.

It also explicitly separates the system-wide fines/carryback cleaner programme from the skirting matrix, noting that cleaner/scraper rollout applies across discharge sections while geometry-specific exceptions such as U4 should be noted separately.

## Contextual Interpretation

The previously drafted eight-column management matrix is too dense for the intended summary-report role and should be replaced.

The revised matrix should focus only on information necessary to understand **coarse-product distribution and side-skirt applicability**.

The universal/system-wide fines cleaner-and-containment programme should be stated separately in short narrative/bullet form rather than repeated row-by-row in the skirting matrix.

## Proposed Simplified Structure

Preferred baseline columns:

1. **Inspected section / conveyor**
2. **Area**
3. **Coarse-product present**
4. **Localized**
5. **Widespread**
6. **Skirting position**

Suggested skirting-position values:

- **IMPLEMENT** — direct early implementation / report-supported requirement;
- **POSSIBLE** — candidate for later site review/adaptation;
- **REVIEW** — first correct/verify another primary contributor before deciding on skirting;
- **NO** — no current audit-supported skirting indication.

A short key should define:

- **Localized** — isolated/local areas rather than general loss along the conveyor;
- **Widespread** — generally recurring along a substantial conveyor length / broad section.

## Layout Principle

For readability, the full asset population may be broken into repeated short tables by material-flow grouping:

- Underground;
- Surface — Screening / Transfer;
- Surface — Loading Station.

This preserves start-to-end coverage without creating one visually dense 23-row table.

## Separate Fines-Control Statement

The Product Spillage section should separately state, in concise bullet/narrative form, that:

- fines/carryback is a system-wide issue;
- the preferred cleaner/scraper functional standard is intended for relevant head/discharge locations throughout the conveyor ecosystem after CV09 proof;
- the preferred normal configuration is the proposed dual-stage self-tensioning arrangement where geometry permits;
- a single effective self-tensioning stage is the constrained exception where two stages cannot be accommodated;
- geometry-specific exceptions such as U4 should be identified separately.

The skirting matrix should not carry a repeated fines/cleaner-control status column.

## Anti-Drift

Do not:

- return to the previous eight-column overloaded matrix;
- mix fines-control rollout status into every skirting row;
- imply that coarse-product presence automatically means skirting is required;
- convert later site/user candidate locations into original audit recommendations;
- use the matrix to reproduce detailed mechanisms or action-register content.

## Next Step

Refine the row-by-row coarse-product distribution and skirting status using the issued audit evidence, then allow the user to mark additional site candidates where the original audit does not establish enough context.


## User Refinement — Column Heading

The user confirmed that the simplified matrix is preferred because separating the fines/scraper programme from the skirting assessment removes information overload and makes each section easier to interpret.

The heading **“Skirting position”** is superseded by:

> **Skirting Requirement Status**

This heading is preferred because it clearly communicates whether side skirting is required, potentially applicable, requires further review, or is not presently indicated.

The status values remain:

- **IMPLEMENT**
- **POSSIBLE**
- **REVIEW**
- **NO**
